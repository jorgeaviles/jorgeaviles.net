## The problem

The project grew from a gap between legacy reporting and the investigations we wanted to pursue. Consultation with Suffolk University on machine-learning proposals in Jupyter notebooks informed the early exploration. The analytical data platform supplied a reusable foundation; the portal connected that foundation with the team's workflows.

## My role and collaboration

I built the Audit Portal with ASP.NET Core and Blazor Interactive Server to connect analytical investigation with operational audit work. The application brings record search, audit detail, lifecycle and progress views, documents, change history, and workbook exports into a permission-controlled workspace.

I am the sole hands-on developer across the analytical notebooks, data platform, and Audit Portal. Audit & Oversight colleagues contribute firsthand knowledge of attorney billing and casework. Their feedback informs analytical assumptions, model iteration, reports, and interface design.

I worked with an IT applications-team database analyst on scheduled master-data extracts and with infrastructure colleagues on role-based access and application-identity permissions.

## From requirements to working capabilities

Search and filters lead from record discovery to a detailed audit workspace. The interface distinguishes stable context, subsequent progress, milestones, and recorded changes. Permitted users edit and save deliberately, with handling for unsaved work and conflicting changes. Validation preserves specified gaps in historical records and checks the information users enter.

Attachments and functioning SharePoint folder synchronization connect supporting material to individual audits. Document-informed AI assistance supports questions involving audit progress, analytical information, and policy guidance. Source references help users distinguish recorded facts, retrieved passages, and generated interpretations. Linked sources support review of document-based answers across an investigation.

## Architecture and trade-offs

**Blazor Interactive Server on Azure App Service.** Application logic and data access stay on the server. Reusable Razor components let me refine the interface primarily in C#. I manage interactive connections, reconnection, server resources, and application state within that architecture.

**Separate responsibilities.** Interface components, feature services, business rules, and persistence have distinct responsibilities. This separation supports focused tests of selected rules and failure conditions.

**Authorization and data integrity.** Microsoft Entra ID provides authentication. Application roles and server-side checks restrict permitted actions beyond visible controls. Managed identities support scoped backend access. Version-aware writes can reject updates based on outdated records.

## Working capabilities and experience

The portal supports approximately 10 staff users in Audit & Oversight. I have observed users updating tracker details without instruction and found the interface responsive for departmental workflows. This qualitative experience informs continued interface refinement alongside departmental feedback.

## Proposed modeling integration

The separate [machine-learning program](/work/machine-learning-audit-prioritization/) investigates predictive scores for human review prioritization. Predictive-score integration into the Portal is proposed and requires evaluation, review, and operational approval before use in reviewer workflows.

## Engineering perspective

A small team's software can still demand careful authorization, data integrity, historical context, and maintainability. Domain feedback helps determine what an analysis or interface needs to make visible, beyond what a database alone can explain.
